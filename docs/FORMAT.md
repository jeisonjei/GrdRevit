# Формат файлов ГЕРС (ПВФ): `.grd` и `.grr`

Версионируется по фактам, проверенным диффом и мутациями реальных файлов
(не по предположениям). «Проверено = …» означает конкретный эксперимент.

## 1. Идентификация

| Поле | `.grd` | `.grr` |
|------|--------|--------|
| Сигнатура (первые байты) | `PWFILEVERINFST___DAT7.00` | `PWFILEVERINFST___RES7.00` |
| Источник | `AUDYTOR 7.3` | `AUDYTOR 7.3` |
| Маркер набора | `SET_7_0` | `SET_7_0` |
| Назначение | проект/исходная схема | результаты расчёта |

Проверено: сигнатура и `SET_7_0` присутствуют в начале обоих файлов.

## 2. Кодировка

- Текст — **UTF-16LE** (как для `.grd`, так и для `.grr`); `ExtractRuns`
  читает оба файла через `Encoding.Unicode`.
- Строки разбиваются на «токены» (раны) нулевыми байтами `00`.
- Числа чаще всего записаны как текст (десятичные строки «16», «2210», «860»).

Проверено: байтовый поиск кириллицы CP1251 в `.grr` дал 0 совпадений,
а в UTF-16LE найден весь русский текст (`С1.`, `ИТП`, `КВ` и т.д.);
`ExtractRuns` (UTF-16LE) корректно выделяет коды приборов, комнаты,
диаметры и маркеры.

## 3. Модель данных (после токенизации)

Файл — последовательность ран. Раны несут один «смысловой токен»
(код прибора, название комнаты, диаметр, число, маркер).

Пример типичного фрагмента: `[код]+ ИТП [комната] [диаметр] [маркер]`.

### Основные маркеры-«переключатели»

| Токен | Значение |
|-------|----------|
| `ИТП` | граница блока прибора: коды слева, комната справа |
| `Выход из распределителя` | начало зоны арматуры/вентилей (не приборы) |
| `ПЕНКА PE 1`, `РОСТ-PEXA-EVOH 7.4`, `ГОСТ…` | зона труб |
| `ПО УМОЛЧАНИЮ…`, `HEIZEN`, `PF_Dat…` | справочник производителей |
| `б м` | (в .grr) — маркер конца списка приборов перед трубами |

Проверено: диффом границ между зонами приборов/труб/арматуры/справочника
в `.grr` (16340 ран) и сверкой счётчиков (552 арматуры в `.grr` ≈ 553 в `.grd`).

## 4. Физическая раскладка (.grd, эталон, 1 692 771 б)

- Заголовок с сигнатурой — первые байты файла.
- Первый смысловой ран — на байтовом смещении ≈ 534.
- Шаг между «главными» записями таблицы приборов ≈ 1020–1044 b
  (инвариантен для соседних ран в начале файла).
- Бэкапы `~grd_A1..H1` — снапшоты одного проекта в разные моменты.

### 4.1 Таблица троек «комната → диаметр → нагрузка»

Первая зона `.grd` (до начала спецификации кодов `TPL/HZ/GS`, т.е. до
ранов `Ariald`/`Arialn`-маркеров) — это таблица **троек**:

    [комната] [диаметр подводки] [нагрузка, Вт]

Примеры из «Бакунинская 77» (раны 0..~630):

    НАСОСНАЯ      16  2210      БКТ 109   21  6010      ЛК 105   10  1740
    С1.210        20  1160      С1.213    22  1930      С2.302   21  1250
    С1.501        22  1780      С2.302    21  1250 ...

Особенности:
- Каждая тройка = **один отопительный прибор в одном помещении**
  (секции `С1.xxx`/`С2.xxx` — жилые помещения: секция.этаж.квартира).
- Диаметр — число 10..32 (иногда `16x2,2`), нагрузка — от сотен Вт.
- Некоторые комнаты имеют только диаметр без нагрузки (нагрузка не задана).
- Зона троек заканчивается на первом ран-маркере `Arialn`/`Ariald`
  перед спецификацией.

### 4.2 Зона спецификации кодов

После маркеров `Arial*` идёт ведомость: коды `TPLCPL*/TPLNE*/HZ-###/GS-…`
с площадями (`0,785`). Это **спецификация/ведомость**, а не привязка
приборов к комнатам — по ней приборы в комнаты НЕ раскладываются.

Проверено: 
- дифф двух разных `.grd` (с/без спецификации) показывает единую структуру,
  расхождение контента начинается с байта 178;
- дифф снапшотов `~grd_A1` vs `~grd_H1` = один изменяющийся байт
  (offset 1 650 355, значение 0x04 → 0x18) — «рев-байт»/счётчик сохранения;
- мутация произвольных байтов (в т.ч. в середине таблицы) НЕ меняет
  ни одного счётчика парсера → **контрольных сумм/длины в формате нет**,
  структура читается динамически по границам токенов;
- количество троек ≈ количеству комнат (218 комнат / 218 приборов для
  «Бакунинская 77»), коды моделей дозаполняются из соседнего `.grr`
  по совпадению мощности (±2.5%, но не более 60 Вт).

## 5. Секции (определены для `.grr`)

| Секция | Раны (пример Бакунинская 77) | Содержимое |
|--------|------------------------------|------------|
| Header | 0..3 | шапка проекта |
| Scheme | 4..12 | название схемы, стояки |
| Devices | 13..1709 | отопительные приборы СО (192 шт, из них 189 с комнатой) |
| PlainList | 175..609 | коды приборов без комнат (ведомость, 420 шт) |
| Tubes | 1710..11732 | трубы и участки |
| Armature | 11733..15491 | «Выход из распределителя» (552 шт) |
| Reference | 15492..16339 | справочник производителей |

Проверено: счётчики Devices+PlainList+Armature=1164,
Armature(from grr)=552 совпадает с числом блоков арматуры по маркеру.

## 6. Незакрытые вопросы (гипотезы)

1. Семантика каждого числового ран внутри спецификации (мощность/длина/координата) —
   для троечной таблицы разрешена: `комната → диаметр → нагрузка Вт`.
2. «Рев-байт» (см. п.4) — смысл значения 0x04/0x18 не установлен.
3. Соответствие `.grd` ↔ `.grr` (проект ↔ результаты): подставляются коды моделей
   по совпадению мощности; полная однозначность без мощности не гарантируется.
